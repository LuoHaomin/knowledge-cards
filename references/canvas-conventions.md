# Canvas 画布约定

## JSON 格式

`.canvas` 是 JSON：`nodes` 数组 + `edges` 数组。

```json
{
  "nodes": [
    {"id": "n00000000000001", "type": "file",
     "file": "<库名>/<板块>/<卡名>.md",
     "x": -400, "y": 200, "width": 300, "height": 100}
  ],
  "edges": [
    {"id": "e00000000000001",
     "fromNode": "…", "fromSide": "bottom",
     "toNode": "…", "toSide": "top",
     "label": "关系说明"}
  ]
}
```

要点：

- `file` 路径**相对于 Obsidian vault 根**（不是库根）。移动卡片文件后必须同步更新此路径——这是 canvas 与 wiki 链接的关键差异（后者按文件名解析、免维护）。
- 节点统一尺寸 **300 × 100**；同画布间距保持 90px+（水平）防误触重叠。
- `id` 用 `n`/`e` + 17 位定长字符串，同一张画布内唯一即可。子画布与总览引用同一张卡时**复用同一 id**（方便同步与合并）。
- `fromSide`/`toSide` ∈ `top/bottom/left/right`，控制连线出入边；`label` 写关系语义（"+光滑结构"、"转移映射"、"存在前提"）。

## 颜色约定

| color 值 | 含义 |
| --- | --- |
| （缺省） | 普通概念卡 |
| `"6"`（紫） | 板块枢纽卡（主线核心概念） |
| `"4"`（绿） | 定理卡 |

## 两级画布体系

- **总览画布**（`知识总览.canvas`）：全库骨架 + 枢纽节点，可手工维护（用户手摆的位置是有效信息，自动布局前先复制副本试验，勿直接覆盖）；
- **板块画布**（`NN-<板块名>.canvas`）：板块内全部卡片，只含板块内部的边；跨板块关系由总览表达。新增卡片后由 Agent 跑布局脚本重排。

## 布局脚本（`布局画布.sh`）

由 Agent 从 skill 目录以绝对路径调用：`bash <skill目录>/scripts/布局画布.sh [--分层] <库根> [画布...]`（画布名为文件名/相对路径时相对库根解析；缺省处理库根下全部板块画布）。脚本不复制进知识库。

- **默认：力导向**（节点互斥 + 边弹簧 + 向心力 + 对齐力），对任意连边结构（含环）稳健；
- `--分层`：依赖 DAG 分层布局（最长路径分层 + 重心法降交叉），适合纯依赖图，兼作**归属审计**——摆位与直觉冲突 ≈ 归属或依赖记录有错；
- 挂边方向按"直线穿盒"法：中心连线方向与四边外法向做点积，出口取最大、入口取最小；
- 调参：`k`（理想边长 330）控制疏密；对齐力系数 0.25 控制横平竖直感；`arep`（4e6）控制互斥。

## 校验清单（每次改画布后）

```python
# 1. JSON 合法 + 边引用存在；2. 节点无重叠；3. file 路径存在；4. wiki 链接无断链
```
