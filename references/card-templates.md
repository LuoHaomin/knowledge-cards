# 卡片模板与写作细则

## 概念卡模板

```markdown
---
tags: [概念]
aliases: [英文名, 常见变体]
---

# <卡名>

> [!abstract] 一句话
> <一句话说清这个概念的本质角色，通常带一个"——"破折号补充它存在的意义>

## 定义

<精确陈述。若讲义/教材有特定记号（如坐标卡三元组），跟随用户主用教材的记号>

## 拆解 / 直觉

<定义的每个条件各挡住什么病态（可用表格）；或一段"人话"解释>
<这一栏是概念卡的灵魂：把定义句和它防御的反例配对>

## 等价刻画（可选）

<同一概念的其他等价表述：等价定义、判据式、构造式。有料才写，没有就整栏删掉>
<例：紧致性的开覆盖 / 序列 / 有限交三兄弟；光滑结构 = 极大相容图册的等价类>

## 性质（可选）

<不显然但承重的性质：继承性（子集/子空间/复合下保留吗）、在操作下的行为（复合/极限/对偶/张量）、边界或极值行为>

## 判据 / 求法（可选）

<实际遇到一个对象时怎么快速验证 / 怎么算出来。例：R^n 中判紧致 = 有界且闭（Heine–Borel）>

## 例子

<正例速查表（空间/对象 | 是否满足），或列点>
<例子要覆盖：平凡例、典型例、边缘例>

## 反例 / 易错点

<最小反例；经典易错（⚠️ 标记）；"定义不要求什么"的辨析>

## 关联

- 上位/前置：<双链>
- 加强/推广：<双链>
- 下游应用：<双链>
- <每行一句话说明关系，如"加一层结构 → [[XX]]">
```

## 定理卡模板

```markdown
---
tags: [定理]
aliases: [英文名, 缩写]
---

# <定理名>

> [!abstract] 一句话
> <定理的"人话"版本 + 它在理论中的地位>

## 陈述

<精确陈述，分条款；有多个版本（如紧版/闭版）时并列并说明差别>

## 推论 / 变体（可选）

<本定理的直接推论、常用特殊化、加强/减弱版本。有料才写>

## 直觉

<为什么该如此；两个条款各司其职时分别命名（如"逼近"与"锚定"）>

## 证明思路

<只记骨架：哪一步需要真正构造（显式写出公式），哪些是标准搬运（一句话带过）>
<证明模式值得命名，如"欧氏情形 + 坐标卡搬运">

## 用在哪

<下游客户名单：领域内哪些结果/构造依赖它（客观、公认）。不写自己项目/研究的用法——那是研究笔记的事。这是承重定理配独立成卡的依据>

## 反例 / 边界

<去掉哪个条件会失效；与相邻范畴（连续/解析版本）的对比>

## 关联

- 依赖：<双链>
- 姊妹定理：<双链>
- 下游客户：<双链>
```

## 写作细则

1. **无定理编号**：不写"定理 2.3.4"。卡片间引用一律用 `[[双链]]` 或语义说法（"两族加细覆盖引理"）。理由：用户可能换教材，编号不跨教材。
2. **无元话语**：不写"建议在画布上放在…"、"（骨架，四步）"这类关于卡片自身/排版的旁白。内容归内容，布局归 canvas。
3. **aliases 尽全**：中英文、新旧术语、常见错拼/变体都挂（例：`漫没/淹没`、`bump function/测试函数/鼓包函数`）。Obsidian 中别名可检索可跳转。
4. **正文也用双链**：首次出现的概念名链接到对应卡；显示文本与卡名不同时用 `[[卡名|显示文本]]`。
5. **表格优先**：例子速查、条件-反例配对、版本对比都适合表格。栏目顺序跨卡保持稳定。
6. **同一反例多处出现、各取一面**：如"双原点直线"在 局部欧氏空间 卡里是病态样本、在 分离公理 卡里是"T₂ 必须独立列为条件"的证明。
7. **深水区占坑**：超出当前章节/论文范围的深刻结论记结论 + 出处，标注"细节以后填"，不展开。
8. **引理寄生规则**：技术性引理挂在最依赖它的概念卡里；只有"会单独问它是什么"的定理才独立成卡。判断不了时问用户。
9. **来源规则**：公认知识（任何教材/综述查到都一样）不标来源；论文特有的定义、记号、结论在卡内标注论文出处（一行：作者 + 期刊 + 年份）。占坑的结论必须有出处。
10. **复合内容拆分判据**：一张卡里混入的非定义内容，逐块问"**会单独问'它是什么/说什么'吗？**"——
    - 会 → 独立成卡（定理直接用定理名）；
    - 不会，但它是本概念成立/非平凡性的依据（存在性保证、与对手概念的区分）→ 寄生在本卡的直觉/拆解或结果小节里；
    - 不会，只是原文后续论证用到的技术引理 → 一行占坑，或并入最依赖它的卡。
11. **知识卡不记个人用途**："我的研究/项目用它做什么"不进卡；客观的领域内下游（哪些著名结果依赖它）可以写进关联/用在哪。

## 写卡自检清单（交卡前逐项过）

模板管呈现（栏目固定、阅读路径一致），清单管采集（防止"模板没引导就不填"）。逐项追问，**有料才落成对应栏目，没有就跳过，不留空栏目**：

1. **换说法**：这个概念有第二种等价表述吗（定义 ⇄ 判据 ⇄ 构造）？→ `等价刻画`
2. **性质**：有什么不显然但承重的性质？子对象继承吗？复合/极限/对偶/张量下行为如何？→ `性质`
3. **落地**：实际遇到时怎么快速验证"是不是"、怎么求出来？→ `判据 / 求法`
4. **例子三档**：正例（平凡/典型/边缘）、**边界例**（刚好踩线满足定义的）、最小反例都齐了吗？→ `例子` / `反例 / 易错点`
5. **定理性内容**：混进卡的定理按拆分判据分流了吗（独立成卡 / 寄生 / 占坑）？
6. **关联**：上位、特例/推广、下游各有没有？每条关系一句话说清，不要裸链接。
7. **来源**：论文特有的定义/记号/结论标出处了吗？

可选栏目（`等价刻画` / `性质` / `判据 / 求法` / 定理卡的 `推论 / 变体`）是封闭词表：用这四个名字，插在固定位置（见模板），不要发明新栏目名——保持跨卡阅读路径一致。某条性质重要到"会单独问它是什么"时，按拆分判据独立成卡，不要把概念卡撑大。

## 生成卡片的协作规则

- 委托批量生成时，先出 1–2 张样板请用户确认/修剪，再批量——用户的修剪（删废话、调侧重）就是校准过程；
- 生成的卡片是草稿，明确提醒用户用自己的话改写；
- 交付时呈现卡片文件本身，并汇报校验（断链/tags）。
